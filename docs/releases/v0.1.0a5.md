# v0.1.0a5 — Alpha pre-release

Easy-To-3D v0.1.0a5 is an Alpha pre-release. It prepares the structural-design
Skill for publication in a skill library and fixes the commands the workbench hands
back to an Agent. Geometry behaviour is unchanged.

## Changes since v0.1.0a4

Publication readiness:

- `SKILL.md` now carries the full header a library parser requires: `display_name`,
  `display_name_en`, `description_zh`, `description_en`, `version`, `author`, and
  three examples per language for the detail page. `tools/build_skill.py` validates
  every required field, the name pattern, the declared version and YAML-plain-scalar
  safety, so a bundle is rejected locally instead of by the upload form.
- The header states what the Skill needs from the machine and how to start it on
  Windows as well as macOS and Linux. A missing backend is handled as a route that is
  blocked, not a design that failed: ask whether it is installed, take its executable
  path, and only then offer an official installation with consent and a real probe.
- `tools/make_skill_icon.py` draws the 512×512 listing icon with the standard library
  only, so the artwork is rebuildable rather than a stray binary.
- `tools/build_skill.py --notes` now writes an upload card carrying the form fields,
  the four answers reviewers ask for (prerequisites, scope, safety, size) and the
  commands to verify a bundle before and after publishing.

Commands that pointed at nothing:

- `doctor`, `delivery-guide` and `review handoff` returned argv arrays beginning with
  `easy-to-3d`. Inside a Skill bundle no such command exists, so an Agent following
  that guidance hit a missing executable. `core/easy_to_3d/entry.py` now derives the
  prefix from the actual entry point: `easy-to-3d` for an installed console script,
  `python3 -m easy_to_3d` for a source checkout, and `python3 <skill>/scripts/et3d.py`
  inside a bundle. `doctor`'s `setup_guidance.configure_command` follows the same rule.

## Included

- Local CLI, bundled browser viewer and structural-design Skill.
- FreeCAD/Blender reference workflows, explicit coordinate handling and static GLB/binary STL import.
- Version-bound comments, review batches, replies, user confirmations and synchronized comparison.
- Immutable project versions, backup verification, STL and drawing delivery workflows.

## Install

Install the wheel with `python -m pip install <downloaded-wheel.whl>` in a Python 3.10+ environment. Extract the Skill ZIP and load the `structural-design` folder using your client's mechanism; the runtime is included. FreeCAD or Blender is a separate installation, and the Skill asks for its path when it cannot find one. See [quick start](../quickstart.md).

Release attachments should contain only the wheel, source archive, Skill ZIP, the
listing icon and `checksums.json`. The manifest records SHA-256 hashes of the
archives. Internal platform-validation bundles are not release attachments.

## Limits

Alpha quality. The viewer does not automatically wake an Agent. Client/model capability varies; see [compatibility](../compatibility.md). Without a local FreeCAD or Blender the Skill cannot produce new geometry; it can still review an existing mesh, import an external result and manage versions. The packaged Skill was verified end to end on macOS (FreeCAD 1.1.4) with 36 viewer checks in Chrome 153.0.8010.12 against the bundled copy. The packaged Skill has not been run on Windows hardware; only the CLI core has. build123d remains experimental. CAD feature history is not recovered from imported meshes. Printing suitability and patent drawing requirements require separate review.
