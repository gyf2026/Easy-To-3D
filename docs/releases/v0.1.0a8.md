# v0.1.0a8

同一个技能，装得更浅。

## 为什么要动

a7 的包里最深的一条路径是 `scripts/easy_to_3d/web/vendor/three.module.js`，离技能根
五层。官方文档和官方打包脚本都没有层数限制，但两份上架实操文都写着「目录最多两层」。
传上去被解析器挡回来的代价，是一次退回重来；把运行时收成一个文件，代价是几十行代码。

## 怎么改的

运行时、查看器和 schema 现在打成**一个文件** `scripts/easy_to_3d.zip`，启动器首次
运行时解压到用户缓存目录，之后直接复用。

```
structural-design/
├── SKILL.md
├── references/*.md
└── scripts/
    ├── et3d.py
    ├── BUILD.json
    └── easy_to_3d.zip      <- 46 个文件收在这一层
```

外层 12 个条目，最深两层。包里那个 46 项的清单只存在于归档内部，上传解析器看到的是
一条路径。

## 首次运行会慢一点

第一次跑命令时解压，之后命中缓存。缓存位置随平台：Windows 用 `%LOCALAPPDATA%`，
macOS 用 `~/Library/Caches`，其他用 `$XDG_CACHE_HOME` 或 `~/.cache`，子目录都叫
`easy-to-3d`，再按构建指纹分一层。缓存可以直接删，下次运行会重建。

并发安全：几个进程同时首次启动时，只有一个把解压结果搬到位，其余检测到已存在就直接用
自己的临时目录收工。缓存目录不可写时退化到系统临时目录，慢一点，但能跑。

## 校验更细了

`scripts/BUILD.json` 现在记三份清单：源文件、随包文件、归档成员。`--check` 因此能
报出是哪一层被动过——归档文件本身的哈希变了，会继续拆到成员级别，直接说是
`easy_to_3d/web/app.js` 而不是「那个 zip 变了」。

`verify()` 里加了层数断言。以后谁再加一个目录，构建直接失败，不会静默发生。

## 顺手修掉的两个真问题

- `entry.cli_argv()` 返回的脚本路径是相对的（`scripts/et3d.py`），Agent 换个工作目录
  照抄就跑不通。改成绝对路径。
- 归档里的文件时间戳固定为 2020-01-01，源码不变则归档字节不变。变了哈希就一定是代码
  变了，而不是 checkout 时间变了。

## 已在本地验过

- 干净目录解压后：`--bundle-info`、`--self-check`、`doctor`（FreeCAD found、launch
  pass）、`project init`、查看器起服务后 `/`、`/app.js`、`/style.css`、`/vendor/three.core.js`
  全部 200。
- 8 个进程同时打进空缓存，全部成功，无残留临时目录。
- 缓存目录设成只读：自动退化到系统临时目录，仍正常。
- 篡改 `app.js` 后 `--check` 报 `state: tampered`，并指名该文件。
- 新增的层数断言与旧版（a7 的 unpacked 布局）兼容：旧包仍能被 `--check` 正确判为
  `stale`，不误报 `tampered`。

包体 546 KB，未超过技能库 3 MB 上限。版本、行为、命令行接口都没有变化。
