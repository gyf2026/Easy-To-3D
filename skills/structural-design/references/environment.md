# Environment

Follow [user workflow](user-workflow.md) for lightweight cached discovery and task-specific probes. Discover host generation, geometry edit, texture edit and local download independently before selecting a route. A client capability report must match the current client/model/tools context; no private host API is inferred by the core.

Run `easy-to-3d --json doctor --backend freecad --probe` or select Blender. `--executable` configures a user-installed path. Found path, launch, script and export are distinct results. Official downloads: https://www.freecad.org/downloads.php and https://www.blender.org/download/ . Do not install Python dependencies into a backend's bundled runtime automatically.

Check the current Agent can execute a harmless command, read/write the selected directory, and actually understand a supplied test image. Persist a capability report containing client/model/tool context, test version, date and evidence. All untested fields remain unknown. Retest session capabilities after changing client/model/tool availability; optional image generation never blocks modeling.

Backend scripts run as separate processes. `run` writes stdout, stderr, argv, timestamps and return status to the workspace. Native software crash does not imply geometric validity or successful export. On failure, inspect logs and retest the affected capability.

On Windows, use the controlled `easy-to-3d run` command for FreeCADCmd scripts. Windows FreeCAD 1.1.4 failed when its script argv contained a Chinese path. The runner provides an ASCII relative entry point that reads the original script through embedded Python, keeping the Unicode workspace, script context and run history. Check `command_adapter` and `effective_command` in execution.json. Do not rename the user's project or retry arbitrary scripts automatically to hide an execution failure. The fixed path passed the Windows10/FreeCAD1.1.4 Chinese-project native workflow on 2026-10-10. The fixed full verifier also passed all 114 core tests without skips on Windows10 AMD64/Python3.13.14, with a 2400-second limit and approximately 1378 seconds elapsed. This does not imply all Windows versions, architectures or tool configurations pass.

When a tool is missing or a probe fails, show the backend's setup_guidance to the user. First ask for the full executable path if it is already installed; otherwise provide the official download link and a system/CPU-matched stable configuration, identifying the project's tested versions rather than claiming the latest version. Rerun doctor with --executable and --probe after setup. Do not require both backends when one satisfies the task; when it is not installed, offer Agent-managed download and installation. Explain the selected backend/version, official source, system/CPU architecture, install location and required privileges, and obtain user consent for that concrete installation. After consent, download and install using available tools, verify official checksums/signatures when provided, configure the executable path and rerun the actual script/export probe. Reuse consent for the same installation. Report actual results and OS-required user interaction; download success alone is not installation success. Discovery failure alone does not authorize installation.
